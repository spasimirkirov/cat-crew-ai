# CatCrewAI

CatCrewAI is the product and the repository (`cat-crew-ai`, package `backend`). Prefer small patches over rewrites. Full product picture: `backend/identity.md` (loaded into every chat turn). Architecture: `docs/ARCHITECTURE.md`. Known debt and backlog: `todo/TECHNICAL_DEBT_AND_OPTIMIZATIONS.md`.

- **Product:** a multi-agent desktop studio. Eight core cats (Cipher, Vanguard, Pixel, Pulse, Aegis, Lex, Blaze, Forge — `platform/catcrew.py`) work a project through the SOP pipeline in `platform/sop.py`. Not a "companion" app.
- **Stack:** Python 3.10+ **FastAPI** backend (`backend/`, `python -m backend`, loopback only), SQLite, cloud model hosts (OpenRouter, OpenAI, Anthropic, Google Gemini, DeepSeek, Groq, Mistral, xAI; no local model host). Front end: **Tauri 2 + React 18 + TypeScript + Tailwind + Font Awesome** in `frontend/`. The API contract is `docs/API.md`.
- **Naming:** project `CatCrewAI`, repo `cat-crew-ai`, package `backend`, env vars `CATCREW_*` (`CATCREW_HOME`), marketplace tools dir `catcrew_marketplace_tools`, hidden workspace dir `.cat-crew-ai`. Never introduce the retired pre-rename name in code, comments, paths or env vars.
- UI, logs, comments, README and chat stay in English.
- Agent tools may edit this tree and any session workspace folders, then `restart_catcrew`.
- **Layout:** the Tauri window opens **Home**, a launcher only (recent projects, New project, Open folder; never tasks). Tasks live inside the project workspace (Fleet / Tasks / Changes tabs and in-chat execution cards). Opening a project enters its **Cat Crew** chat (the orchestrator; wire id `crew`, avatar `default.png`; not an agent, so never a column in the Skills / Tools matrices and never looked up in `agent_tools` / `agent_skills`); each cat also has a 1:1 thread. Sidebar items pop in live over `/ws/events`. Activity cards are clamped to two lines (`line-clamp-2`) with a "See more" toggle. Palette: `#0B0D12` background, `#13161F` cards with a 1px `#222634` border, cyan `#38BDF8`, emerald `#34D399`, violet `#A78BFA`, muted `#8B92A8`, Inter. Icons are Font Awesome.
- **Brains:** cloud hosts only (OpenRouter, OpenAI, Anthropic, Google Gemini, DeepSeek, Groq, Mistral, xAI), each with its own key; every key (hosts, Brave, TypeSafe for Jev) lives in one write-only catalog (`services/api_access.py`, `/api/keys`, **Models → Hosts**). Jev, the decision model, runs on OpenRouter or TypeSafe's official API. Images and Vision can be Off. The **Models** page picks a model per role (Chat, Coding, Memory, Vision, Planning, Review, Fallback, Images), each with an (i) tooltip on what it does and what kind of model suits it; an unset optional role follows Chat, except Review (the model QA checks the build with), which follows Coding, and Fallback (the model a run switches to when its model is rate-limited or out of credit), which unset means no failover. Host keys are write-only on **Models → Hosts**. Model lists and capability badges (vision / reasoning / tools) come live from each host, and start-up checks that every chosen model still exists (a notice lists the ones that do not). A chat over 8,000 tokens is summarised by the Memory model before it reaches the next model. Settings → API Access holds the optional search key (Brave); Settings → Connectors holds GitHub / Linear / Notion / Slack / MCP tokens (deferred tool schemas); Settings → Skills lists playbooks. Command timeout, tool-round cap (0 = unlimited for chat) and tool approvals: Settings → General (not `.env`). Pipeline work orders get a round budget per phase (`sop.PHASE_BUDGETS`: planning 15, build slice 60, QA 60 ...), a producing phase is stopped after 12 rounds in a row that changed nothing (the stall guard), and a work order that ran out of rounds while still making progress is continued once automatically.
- **Pipeline:** Vanguard's distribution ends with `## Work orders` (the build runs them one at a time) and `## Acceptance checks` (`GET /path -> 200, shows "text"`; the harness requests each URL before QA). QA writes automated tests (skill `automated-testing`) and re-runs them; on FAIL the developer fixes and QA checks again, up to three checks. "continue" / "try again" (or `hand_off_to_crew` with `resume`) finishes the planned run from its first unfinished phase instead of planning again. If Cat Crew's chat reply promises a hand-off without calling the tool, the hand-off happens anyway. After any cat changes files, the harness checks the project itself (`harness/project_check.py`: `php -l`, Blade views compiled and linted, `npm run build`, pages without a 5xx) and hands a failure back to the same cat, up to two fix runs, before its work counts.
- **Agents are read-only:** the eight core cats are defined in `platform/catcrew.py` and upserted on every start; the Agents page only shows them (no create, edit or delete). QA screenshots with a bare name go to `data/screenshots/<project>/`, never into the client's project.
- **Search / images:** DuckDuckGo via `ddgs` (optional SearXNG or Brave key). Images: hidden local ComfyUI on a separate process (`generate_image`, `comfy_run_workflow`); never unload the chat LLM for it. Existing photos: `image_search`.
- **Sessions / workspace:** a project's computer is `Project.folders` in the catalog. Everyone and 1:1 chats share it. No folder means tools use `data/scratch/<session-id>/`. Never default the app install tree as a project folder. Attaching a project that already has a `.gitignore` appends `.cat-crew-ai/` if missing; never create `.cat-crew-ai` or a new `.gitignore` for it. Skills load from `backend/skills/`, optional `CATCREW_HOME\skills\`, and an existing `<workspace>/.cat-crew-ai/skills/`. `AGENTS.md` / `SYSTEM.md` load only from attached folders.
- **Persistence:** identity catalog in `data/platform/registry.json`; operational ledger (tasks, file diffs, skill and tool assignments) in `data/platform/catcrew.db` (`platform/db.py`); run supervisor rows in `data/platform/catcrew_state.db`. SQLite changes are additive only (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ... ADD COLUMN`) — never drop or rewrite existing tables.
- **Context isolation:** a specialist receives only its system prompt, its assigned task and the relevant file diffs. Never paste global conversation history into a specialist prompt.
- **Developer coding:** tools first, small patches, `search_files` is not Python-only, fetch official docs, `read_skill coding-companion` for long scaffolds. Use `update_todo` for the harness checklist — do not rewrite it with `write_file`. Prefer `run_subagent` / `run_code_mode` when they keep context cheaper. Never paste tool-call JSON into the chat. Pass `cwd`, not a lone `cd`. Composer: while the agent works, Send queues the message and Steer injects it into the running turn.
- **Window rules:** the native window is created hidden with the app background colour (`frontend/src-tauri/tauri.conf.json`) and shown by the front end after its first paint (`frontend/src/lib/window.ts`), so nothing flickers. Never do blocking DB or LLM work on the API event loop: run it in a worker thread and publish through `backend/platform/bus.py`. The front end never talks to SQLite or the filesystem directly; it only uses the API.
- Session tree: jump to an earlier turn; branches stay in the JSON. Slash templates: `/review`, `/commit`. In-chat activity is a two-line execution card ("N steps · Xs") with a **See more** toggle.
- Node is used only for the front end (`frontend/`). Agent and harness logic stays in Python.
- After a code change, `python -m compileall -q backend` then `python -m pytest -q` is a reasonable smoke check; for the front end `cd frontend && npm run typecheck && npm test`.
- After a harness change (prompts, the tool loop, steers, tool results), run `python -m backend.evals` against a real model before and after, and compare the saved runs with `--compare` (pass rate, rounds, tokens).
- Self-knowledge: every chat turn loads `backend/identity.md` plus the skill index. Playbooks stay on `read_skill`.
