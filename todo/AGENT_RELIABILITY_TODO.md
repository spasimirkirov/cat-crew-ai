# Agent reliability: todo and status (20 September 2026)

Symptom: every cat eventually ends a turn with "I got stuck repeating the same failed tool", the designer cannot finish a design any more, and long runs burn tokens. Findings and design: `docs/PI_EVALUATION_AND_AGENT_PLAN.md`.

## Done in this pass

- [x] **Why "got stuck" happens.** Two guards were blind to progress. `BaseProvider.run_agent` skipped any identical tool call for the rest of the turn, and `platform/runner._exec_and_log` throttled the same call after two runs. So `npm run build` -> fix a file -> `npm run build` was treated as a loop and skipped, and two skipped rounds ended the turn. Fix: `harness/loop_guard.py` (`WorldClock`): a repeat only counts while no tool that can change the project has run in between. Streak limit is 3, the skip message quotes the earlier result, the final message names the tool and its error.
- [x] **Contradictory steer texts.** `_EXPLORE_STEER` told cats to run `npm create vite@latest` (forbidden by the runner rules); `_REDELEGATE_STEER` named legacy bots. Both rewritten.
- [x] **Designer regression.** The `designer` role pack had no `run_command`, `update_todo`, `search_files`, `create_directory`, `get_file_info`, `read_terminal`, git read tools, while the prompt requires `update_todo` and the cat needs to build what it styles. Added. The "tool is not available" error now lists the cat's real tools and how to report a blocker. `architect` gets `report_task_results`.
- [x] **A stuck QA turn read as a pass.** `_qa_verdict_failed` now treats "I got stuck" as a failure, so the developer gets the tool and error text and QA is re-run once.
- [x] **A-02 blind heal retry.** The healing child run now receives the failed verification output (original task plus the failure).
- [x] **Context.** The phase hand-off (`prior`) is capped (1,200 characters per phase, 4,500 total, "Computer after this turn" listing dropped) and points to BLUEPRINT.md / ARCHITECTURE.md / TASKS.md / BUILD_STATUS.md. Compaction pins the original assignment verbatim (also across repeated compactions) and no longer counts the system prompt against the limit; default `CATCREW_CONTEXT_TOKENS` 8,000 -> 12,000.
- [x] **Tests.** `tests/test_loop_guard.py`, `tests/test_agent_regressions.py` (end to end through `run_delegated` / `run_bot` / `execute_tool`, real `npm run` scripts). Both fail on the old behaviour. No new failures in the rest of the suite (19 failures, all in modules already known to be stale, or PermissionError from the sandbox).
- [x] **Essential vs optional tools.** `platform/essentials.py` defines what each role can never be without (built-ins per role, plus registry tools such as Aegis's browser set and Pulse's `write_file_patch`). Essentials are always attached: prepended in `builtin_names_for_role` (an agent's `tools` list can only choose optional ones), re-attached on every start by `ensure_role_tools`, bound by `register_agent_tools` even without a DB row, refused by `PUT /api/tools/{id}/assignments` and `DELETE /api/tools/{id}` (409), and shown with a lock in the Tools matrix and drawer (`locked_agent_ids`). Every specialist now has `update_todo` and `report_task_results` (Lex, Blaze and others could not report their task before), and writers have `replace_in_file` / `create_directory`. Optional, toggleable: web search, image generation, `browser_look`, `browser_select_option`, `read_code_ast`, Docker and VPS probes, and the rest of each pack. Tests: `tests/test_essential_tools.py` (7), two in `Tools.test.tsx`; `tsc` clean.
- [x] **Registry tools never ran (found while testing the bug flow).** `execute_tool` answered `unknown tool` for every Letta-style registry tool (the whole browser set for Aegis and Pixel, `write_file_patch`, `git_diff_inspector`, `create_fix_task` ...) although they were advertised in the cat's schema. A cat that retries a tool that cannot work ends the turn with "got stuck repeating the same failed tool", and the designer had no working browser checks. `execute_tool` now falls through to the tools bound for the turn (`harness/deferred.execute_loaded_tool`) before it says unknown. Test: `test_a_bound_registry_tool_actually_runs`.
- [x] **A QA FAIL was never seen.** The runner wraps a reply as `[Name / role]` + reply + directory listing, and `_qa_verdict_failed` looked for FAIL at the very start, behind that header. So a real FAIL verdict never sent the developer back. `_qa_verdict_body` now strips the banner, the header and the listing (also accepts `**Verdict: FAIL**`). Test in `tests/test_loop_guard.py`.
- [x] **Work orders in the ledger.** Additive migration on `project_member_tasks`: `kind` (build | bug | plan | fix | review, default build), `parent_id`, `acceptance`, `depends_on`, `attempt`, `reported_by`. `create_task(...)` takes them, `list_child_tasks(parent_id, kind)` reads them, `GET .../tasks` returns them. - [x] **Problem report -> lead -> fix plan -> fix -> QA (`platform/bugflow.py`).** `POST /api/projects/{pid}/threads/{bot_id}/report` (and the "Report problem" button next to Send, in a cat's chat and in Cat Crew) starts one bug turn in the Cat Crew room: a `bug` task for Vanguard, who gets the report plus ledger facts in a fresh context and writes the plan by calling `create_fix_task` (an essential Vanguard tool, at most 6 steps, assignee validated).
